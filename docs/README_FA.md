# راهنمای فارسی سرویس BiRefNet Lite

این پروژه یک سرویس مستقل برای **حذف پس‌زمینه تصویر روی CPU** است. دو کانتینر دائمی دارد: `api` با FastAPI و ONNX Runtime، و `ui` با React و Nginx. تصویر ارسالی روی دیسک ذخیره نمی‌شود و وزن مدل یک‌بار به Volume دانلود می‌شود.

## راه‌اندازی

```bash
cp .env.example .env
# برای محیط Production مقدار APP_ENV=production و API_TOKEN امن را تنظیم کنید.
make build
make model
make model-verify
make up
make ps
make health
```

آدرس پیش‌فرض پنل: `http://127.0.0.1:8082` و API: `http://127.0.0.1:8001`. پورت داخلی API همچنان `8000` و Nginx برابر `80` است؛ فایل `.env` موجود بر پیش‌فرض‌های Compose اولویت دارد.

برای ساخت توکن مناسب می‌توان از `openssl rand -hex 32` استفاده کرد و مقدار تولیدشده را فقط داخل `.env` قرار داد. فایل `.env` نباید در Git ثبت شود.

## سرویس و پردازش

- `POST /v1/remove-background`: دریافت تصویر و تولید PNG با شفافیت.
- `POST /v1/mask`: تولید ماسک خاکستری.
- `GET /health/live`: بررسی زنده‌بودن پردازش API.
- `GET /health/ready`: بررسی بارگذاری و گرم‌شدن مدل.
- `GET /v1/models`: اعلام مدل و تنظیمات پردازش.
- `GET /metrics`: متریک‌ها برای Prometheus.

در پردازش، تصویر با EXIF تصحیح می‌شود، به RGB با اندازه ۱۰۲۴×۱۰۲۴ تبدیل می‌شود، نرمال‌سازی ImageNet روی آن انجام می‌شود و سپس ONNX Runtime صرفاً از `CPUExecutionProvider` استفاده می‌کند. خروجی Logit با Sigmoid به ماسک تبدیل و به ابعاد اصلی تصویر برگردانده می‌شود.

## فایل مدل

وزن ONNX به‌صورت جداگانه از `onnx-community/BiRefNet_lite-ONNX` دریافت می‌شود و منشأ آن `ZhengPeng7/BiRefNet_lite` است. فایل مدل در ZIP قرار ندارد؛ دانلود پیش‌نیاز راه‌اندازی است. SHA256 به‌صورت اجباری بررسی می‌شود و اگر مقدار مطابق نسخه ثبت‌شده نباشد، سرویس بالا نمی‌آید.

## محدودیت‌های این نسخه

- کیفیت روی نمونه‌های واقعی و زمان P95 روی CPU هدف باید Benchmark شود.
- هر دو Docker Image روی Ubuntu ساخته شده‌اند و وزن مدل با SHA256 تأیید شده است، اما Startup واقعی ONNX در محدودیت‌های 3g، 4g و 5g به علت OOM شکست خورده و تست نهایی UI انجام نشده است.
- تست‌های Backend با موتور شبیه‌سازی‌شده انجام شده‌اند؛ جایگزین آزمایش مدل واقعی نیستند.
- برای محیط عملیاتی باید HTTPS، کنترل هویت کاربران، Rate Limit در Ingress و نظارت مصرف CPU/RAM را اضافه کنید.
- با داشتن سخت‌افزار واقعی می‌توان `CPU_THREADS` و `MAX_CONCURRENT_INFERENCE` را تنظیم کرد.

مستندات کامل در `README.md` و فایل‌های `docs/` قرار دارد.
